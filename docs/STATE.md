# Project state

## Audit (2026-10-15, before the reliability work)

What existed (commit `0d29680` snapshot):
- UI screens: home, alarm setup, sleep mode, stats, settings, sounds, lights, onboarding,
  local login/signup (plaintext passwords in SQLite, no backend, login gated the app).
- Modules: sleep-analysis (audio + accel features), alarm-engine, notifications, sound,
  Hue/Yeelight lights, bedtime calculator, i18n en/fr, SQLite profile/sessions.
- 5 jest test files, but no `test` script. `tsc` had 1 error (DevToolsScreen).

What did **not** work:
- **The alarm could not fire reliably**: it relied on JS `setTimeout`/`setInterval`.
  The native `AlarmModule` it called did not exist, `AlarmEngine.initialize()` was never
  called outside the dev screen, and nothing consumed the trigger. App killed, Doze or
  screen off meant no alarm.
- **No motion was recorded at night** in production. The accelerometer and microphone
  were only wired in the dev screen. `expo-background-task` was installed but unused.
- Smart-wake logic counted light epochs rather than consecutive ones (bug), and was never fed data.
- No morning summary beyond a "last night" card holding only the duration.
- This clone was missing 8 commits from origin (tracked `android/`, release CI, SDK 57
  fixes). They were merged into the work below.

## After this work

- Native local module `modules/smart-alarm` (Kotlin):
  - fallback alarm via `AlarmManager.setAlarmClock` (exact, Doze-proof, app-killed-proof,
    re-armed after reboot/time change);
  - foreground service recording the accelerometer all night (wake lock);
  - native wake decision inside the window, ringing service plus a lock-screen activity.
- JS: night analysis (calm/light/wake estimate), summaries stored in SQLite, new home,
  sleep mode and night summary screens. The login gate is removed (the code is kept).
- See `docs/SCIENCE.md` for the rationale and limits.

## Known limits

- Phone movement is only a rough sleep-stage proxy (see SCIENCE.md).
- If the phone is on the bedside table, nothing moves: the alarm rings at the target time.
- If the tracking service is killed (aggressive OEM battery savers), the smart part is
  lost but the fallback alarm still rings. Disable battery optimisation for the app.
- Legacy modules (lights, sounds, auth, onboarding quiz) are unchanged and not part of
  the core flow.

## Rename (2026-10-17)

- The app is now called **Aube** (launcher label, titles, release asset `aube-vX.apk`). Package id `com.poirouxmartin.smartclock` unchanged so updates install over existing versions.
- New dawn icon (rising sun over the horizon) generated by `scripts/generate_icons.py`.

## Version 1.3.0 (2026-10-20)

Nouveautés :
- **Détection automatique du sommeil** (sans bouton, activée par défaut) : alarme quotidienne
  armée, sondes toutes les 15 min en soirée, score pondéré (Sleep API, immobilité, obscurité,
  heure habituelle, charge), démarrage du suivi au premier endormissement, faux départ annulé,
  notification « Déjà réveillé·e ? ». Modules : `AutoManager`, `ProbeReceiver`,
  `SleepApiReceiver`, `SleepOnsetDetector`, `AutoSchedule`, `UsualBedtime`.
- **Sons de nature** (oiseaux, vagues, forêt, pluie, ruisseau ou sonnerie système), montée de
  volume exponentielle depuis 2 % (30/60/120 s), vibration après la montée. Modules :
  `VolumeRamp`, `NatureSound`. Licence : `docs/sounds-license.md`.
- **Aube lumineuse** (`DawnActivity`, `DawnCurve`) : 15/30/45 min avant l'alarme, luminosité
  et couleur progressives, torche optionnelle en fin d'aube.
- **Fenêtre de réveil** (`WakeDecider.decide`) : seuil personnel P90, mouvement soutenu, signal
  Sleep API, ajustement près des cycles de 90 min. Justification : `docs/science-reveil.md`.

Tests : Jest 105 tests (7 suites) via `npm test` ; Kotlin 47 tests via
`cd android && ./gradlew :smart-alarm:testDebugUnitTest` (WakeDecider, SleepOnsetDetector,
AutoSchedule, UsualBedtime, DawnCurve, VolumeRamp, NatureSound).

## Limites / à valider

- Pas encore validé sur une nuit réelle ni sur un appareil de test.
- La Sleep API dépend de Play Services et de la permission `ACTIVITY_RECOGNITION` (optionnelle).
- L'actigraphie du téléphone ne distingue pas réellement les phases de sommeil : le gain
  attendu est modeste (voir `docs/SCIENCE.md`).
- La lumière de l'aube sur écran de téléphone est très en dessous des 250-300 lux des études.
- Doze et les tueurs de tâches constructeur peuvent retarder les sondes : demander d'ignorer
  les optimisations batterie.
- La torche pointe vers le matelas quand le téléphone est posé écran en l'air : désactivée par défaut.
- Le score d'endormissement peut se déclencher pendant une lecture au lit, téléphone immobile :
  l'endormissement est alors estimé trop tôt.
